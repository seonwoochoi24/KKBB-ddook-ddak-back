# jev로 먼저 구성하는 금융 화면

`POST /api/canvas`는 jev 위젯 선택 → 서버 검증 → 필요한 데이터 조회 → 기존 위젯 JSON 반환 순서로 처리합니다. 깨비 인사말은 `필요한 기능을 모았어요.`라는 고정 문구이며, 별도 설명 AI 호출이나 뒤늦은 설명 생성은 구현하지 않았습니다. 기존 코드의 인사말도 템플릿이었으므로 설명 생성을 제거해서 빨라졌다고 주장하지 않습니다.

## 실행

```bash
export JEV_AI_API_KEY="your-jev-api-key"
./mvnw spring-boot:run
```

GPT 비교 실험을 제외하면 `OPENAI_API_KEY`는 필요 없습니다. 기존 OpenAI 코드와 jev/GPT 비교 API는 유지했습니다. 기본 경로는 기존 검증된 jev 연결 코드를 재사용하며 공급자 선택은 서버가 `jev`로 고정합니다.

## 응답 계약

기존 프론트가 읽는 `greeting`과 `widgets`를 유지하고 `status`를 추가했습니다.

- `ready`: 검증된 위젯 반환. 실제 거래 완료를 뜻하지 않습니다.
- `empty`: 빈 입력, 외부 호출 없음.
- `unsupported`: 선택된 기능 없음.
- `needs_clarification`: 불확실한 선택, 충돌하는 입력, 환전 통화 미확인. 이번 응답의 위젯은 비어 있습니다.
- HTTP 400: 2000자 초과.
- HTTP 502/504: 공급자 오류·잘못된 선택 응답·시간 초과.
- HTTP 503: jev 키 미설정.

기존 프론트는 `status`나 오류 문구를 아직 표시하지 않을 수 있습니다. 이 변경은 백엔드만 적용했으며 프론트 연동 시 확인이 필요합니다.

## 파라미터와 한계

추가 GPT 호출을 피하기 위해 알려진 도시·국가의 통화와 명확한 금액·기간만 서버 규칙으로 읽습니다. 예: `일본 3박4일 여행 2만엔 환전과 보험`, `상하이 2,000 CNY 환전`, `USD 100 환전`.

지원 범위는 `CanvasParameters`의 목록과 패턴에 한정됩니다. 모임 이름은 별도 추출하지 않고 기존 일반 문구를 사용합니다. 여러 목적지·통화·금액, 소수 외화 금액 등 현재 정수 금액 계약으로 표현할 수 없는 값, `1만5천엔`·`오천엔` 같은 지원하지 않는 금액 표현은 확인을 요청합니다. 날짜 범위·범용 한국어 수사·문장 내 부정/수정의 완전한 정보 추출은 구현하지 않았습니다. 명시 외화 금액이 없으면 기존 위젯의 기본 제안 금액을 사용합니다.

서버는 미등록 위젯·중복·3개 초과·`needsReview`를 검사합니다. 신뢰도 임계값은 기존 실험 설정을 재사용한 것으로 실제 정확도 보장을 뜻하지 않습니다. jev는 선택만 하므로 입력 문장의 의미를 잘못 해석할 가능성은 남습니다.

환율 조회는 기존 동기 경로를 유지하므로 캐시 미적중 시 화면 응답에 시간이 더 들 수 있습니다. 실제 계좌·카드 정지·보험 가입 등 금융기관 연결 및 기존 시연 데이터는 이번 범위에서 변경하지 않았습니다. 멀티턴 대화·스트리밍·지연 설명 생성도 이번 구현에 포함하지 않습니다.

## 확인

```bash
./mvnw test
```

API를 대신한 응답으로 선택·파라미터·오류·기존 JSON 호환성을 검증합니다. 유료 API 호출이나 전체 속도 재측정은 수행하지 않았습니다. 기존 jev 평균 219ms는 위젯 선택만 측정한 과거 결과이며 이 엔드포인트 전체 지연으로 사용하면 안 됩니다.
